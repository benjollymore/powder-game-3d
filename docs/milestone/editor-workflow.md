# Full editor input workflow

`tests/milestone/editor_workflow_gpu.gd` drives the production editor with `Input.parse_input_event` for buttons, keys and gestures, plus `Input.warp_mouse` to synchronize the OS cursor with each intended pointer position. The editor `_process` loop, TimeController frame loop and Input singleton button state stay active throughout. The test temporarily disables input accumulation for deterministic event delivery; it does not disable the frame loops, call editor paint handlers, emit button signals, write simulation voxels, or invoke editor action methods directly.

The workflow selects Wall through the actual palette button, changes brush size by keyboard, holds a primary press over several frames and makes a fast connected ramp stroke. It clicks Undo and compares the complete packed world with the original. It then redraws the ramp, selects Sand and paints above it, navigates through Option-primary drag plus injected pan/pinch, and clicks Center. All navigation must preserve exact material/history.

Run, Pause, Single step, Resume and Return use actual GUI mouse press/release events. The workflow verifies paused bytes/ticks, a one-tick step, a paused brush click consumed by the next step, a held live source surviving the normal Input polling guard, separate authored history, exact Return, and Undo after Return. Screenshots capture the authored ramp, paused experiment and restored Build under the supplied output directory. The verified authored bytes are also exported as `painted-ramp.p3d` through ArchiveJob for reuse; that explicit artifact export does not test the native Save dialog.

These are injected **Godot button/key/gesture events with a warped OS cursor**, not physical Mac trackpad validation. Godot documents that `parse_input_event` feeds engine input but does not move the operating system cursor. A preliminary headless probe retained the injected viewport position; the visible macOS run did not. Its per-frame cursor poll replaced that position with the real cursor outside the window, canceling live sources and causing two material checks to fail. Synchronizing the cursor with the documented warp API corrected the harness while leaving production frame processing active. The test saves the global cursor position, restores it using window-relative warp coordinates, and verifies restoration within two pixels. No native file dialog is exercised. See [Godot Input documentation](https://docs.godotengine.org/en/stable/classes/class_input.html#class-input-method-parse-input-event) and [DisplayServer warp coordinates](https://docs.godotengine.org/en/4.6/classes/class_displayserver.html#class-displayserver-method-warp-mouse).

```sh
godot --path . --resolution 1280x800 --always-on-top --disable-vsync -s res://tests/milestone/editor_workflow_gpu.gd -- grid=128 output_dir=/tmp/editor-workflow
```

The expanded input route exposed a keyboard ownership bug: after a palette/Undo/Reset button had focus, Space reached the editor's late `_unhandled_input` handler on press, then the focused Button also activated on release. The editor now claims plain Space in `_input` before GUI dispatch and retains ownership through release. Echoes cannot retrigger it. LineEdit/TextEdit focus, modified Space, another window and an open OptionButton popup retain their own input; native archive dialogs already suspend editor input. Enter remains available for keyboard activation of GUI controls.

`tests/milestone/editor_keyboard.gd` checks this policy headlessly using the real input code and real Reset/Undo buttons, replacing only their effects with counters. It assigns keyboard focus explicitly for that small regression. The GPU workflow additionally clicks Undo through parsed mouse events, then sends Space and counts the actual button signal to verify that a focused GUI action is not duplicated. This is separate from the workflow's ordinary GUI Run/Return path.


Validation: **24 GPU workflow checks**, **6 headless keyboard-ownership checks**, **9 existing phase-input checks**, and **10 native gesture routing checks** passed. Both the editor and TimeController `_process` loops stayed active for the GPU session. The final run contained 587 authored sand cells, 588 after the paused click's single step, and 596 after the live hold. The live hold uses wall time and proves continued real emission; its exact count varies with delivered simulation ticks and is not a frame-rate or determinism benchmark. Matched-tick source determinism is tested separately.

Committed evidence is under `workflow-evidence/`: the run log, authored and paused screenshots, and the **128³** `painted-ramp.p3d` fixture. Open that fixture in a 128³ session. The screenshots were inspected: the painted ramp and sand are visible, and the paused experiment shows sand resting/sliding along the ramp. Water foam is still visually bright; this workflow does not claim the rendering quality is finished. The third restored-Build capture is generated by the harness but omitted from committed evidence because exact restoration is checked against all packed bytes.
